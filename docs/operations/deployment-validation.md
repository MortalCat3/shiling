## 已实现的部署基线

- Local 存储 Compose：PostgreSQL、一次性迁移、API、worker、执行关闭的 preview、Caddy/Web。
- 运行/迁移/测试 URL 分离；随机 secret 文件生成入口；专用数据库、schema owner 与最小权限运行角色。
- 非 root 应用镜像、只读根文件系统、持久对象卷、内部网络和 Caddy 同源反向代理。
- 初始化、健康/就绪、备份、较早备份恢复、版本升级和回滚操作说明。
- 动效 preview 不接收数据库 URL、主站 secret 或原件卷，不对公网反代，执行能力固定关闭。

## 上线阻断项

以下任一项未完成时，不应把当前仓库声明为生产就绪：

1. 目标 Linux/CPU 架构镜像构建、首次安装、进程重启、持久卷和 HTTPS 验证。
2. 代表性媒体、目标浏览器/设备及约定负载下的成功与受控失败验证。
3. 一致备份可取回、较早备份安全恢复、升级和回滚演练，并记录实际 RPO/RTO。
4. 生产 secret、域名、数据库权限、磁盘、日志脱敏、告警和安全审查。
5. 若要开放动效：完成独立主机和服务器执行器隔离；若无法完成，持续保持关闭。
6. 若选择阿里云 OSS：完成目标 Bucket/RAM/HTTPS 与恢复验收；本地协议测试不代表供应商验收。其他 S3 仍需独立适配。

操作顺序见[Compose 指南](../../deploy/compose/README.md)和[备份、恢复、升级与回滚](backup-restore-upgrade.md)。生产前不得用“临时放宽权限”“启用超级用户”“将对象目录暴露为静态文件”或“在主站 iframe 直接运行动效”来绕过这些门槛。
