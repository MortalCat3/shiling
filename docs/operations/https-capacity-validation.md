# 本机 HTTPS 与容量验收

- 日期：2026-11-17；承接[Docker 部署/恢复验收](docker-local-validation.md)。
- 环境：macOS ARM64、Docker Desktop 29.8.2 / Compose 5.5.1；Linux ARM64 容器；Docker 可用 10 vCPU、约 7.75 GiB 内存。
- 组件：Node 24.22.3、pnpm 12.21.0、PostgreSQL 18.7、Caddy 2.11.9、worker FFmpeg 5.1.9。
- 数据范围：全新隔离实例、随机合成账号、确定性噪声图片和测试图案 MP4。无宿主数据库、历史素材、外部存储或真实用户数据。

本机 HTTPS、Secure Cookie、反向代理、1/4/8 并发上传、真实任务处理、排队恢复和上传字节边界已经通过。权限规则没有放宽，动效上传及执行继续关闭。结果是本机短时合成基线，不是生产容量上限或 SLO 承诺。

## 发现与修复

实测发现不同 IP 的客户端被错误合并进 Caddy 地址的登录限流桶：A 触发限流后，独立客户端 B 也返回 429。原因是 API 默认不信任转发头，`request.ip` 得到直接代理地址。

新增 `SHILING_TRUSTED_PROXY_HOST`：直连默认关闭，Compose 指向受控服务名 `web`。API 仅信任该名称解析出的相邻地址和直接一跳；缓存会随代理地址变化更新，DNS 失败清除旧信任，不开放全网或仅按跳数信任。Caddy 保持默认转发头处理。该实现遵循 [Fastify 的代理信任边界](https://fastify.dev/docs/latest/Reference/Server/#trustproxy)与 [Caddy 转发头规则](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy#defaults)，也核对了仓库实际安装版本。

修复后的真实双客户端测试：A 连续 10 次错误登录返回 401，第 11 次为 429；每次更换伪造 X-Forwarded-For/X-Real-IP 仍不能绕过。B 同时仍返回正常凭据拒绝 401，没有受 A 的额度影响。另有 3 组 API 安全测试覆盖非可信直连、转发链、IPv4 映射、DNS 更新/失败、默认关闭与非法配置，已加入 `pnpm check`。

Compose 另显式传入核验/处理并发参数，默认仍各为 2。没有提高权限、上传上限或资源限制来让测试通过。

## HTTPS 与 Cookie

使用 Caddy 本地 CA，只向本次 Node/curl 验收客户端提供公钥证书。没有修改系统信任或 hosts，没有使用 `-k`、关闭 TLS 验证或外部证书申请。客户端显式映射回环端口，逻辑来源为 `https://shiling.test`。

| 检查            | 实际结果                                                                                        |
| --------------- | ----------------------------------------------------------------------------------------------- |
| TLS             | 正确 CA/主机名握手成功；未知 CA、错误主机名拒绝                                                 |
| HTTP 重定向     | 308 到 HTTPS，路径与查询参数保持                                                                |
| 会话属性        | `__Host-shiling_session`、Secure、HttpOnly、SameSite=Lax、Path=/，没有 Domain                   |
| Cookie 实际行为 | curl Cookie 引擎在 HTTPS 认证成功；不发送到明文 HTTP 或兄弟域名；退出后 jar 中的会话被清除      |
| CSRF/来源       | 缺少 CSRF 和不可信 Origin 均 403；无会话 401；退出后的旧会话 401                                |
| 反代与私有路径  | API、原件交付、Range 正常；`/objects/`、`/uploads/`、`/preview/`、`/internal/` 均 404           |
| 公开权限        | 普通成员无法读取管理设置；管理员不能代发成员素材；所有者公开后游客可经 HTTPS 下载，原件摘要相同 |
| 动效            | 能力显示关闭，创建 HTML 上传返回 403；运行概览报告执行关闭                                      |

兄弟域名仅是返回 404 的测试探针，不连接 preview，不执行上传内容。此处验证的是 TLS 客户端和 Cookie 引擎行为，没有宣称目标浏览器/真机证书信任、公共 CA、DNS 或自动续期已经通过。

### 超限与失败恢复

- 精确 100 MiB PNG 上传、处理、原件摘要通过；使用低像素和合法私有 ancillary chunk 填充，只验证字节边界与流式交付，不代表 100 MiB 高像素图像性能。
- 超过上限的声明、传输 Content-Length 均 413；实际超过 2 MiB 的品牌 multipart 文件为 413，服务随后仍就绪。
- 损坏图片返回安全处理失败；摘要不符为 `UPLOAD_CONTENT_MISMATCH`。
- 中断上传进入失败态，重试传输后 ready、原件摘要相同；没有永久删除操作。
