# 账号与管理界面验收（第三批）

后续已补做[三批真实 API 验收](real-api-workbench-validation.md)。本文保留第三批前端开发时的证据与限制，真实服务端、品牌上传和账号生命周期的最新结论以该记录为准。

日期：2026-11-17。范围依据 [ADR 0005](../adr/0005-interface-redesign-scope.md)，沿用 B「创作工作台」与 [DESIGN.md](../../apps/web/DESIGN.md)。

## 实现范围

- 账号：个人信息、密码修改、退出全部会话；邀请、恢复、初始化与再次确认身份使用同一套表单规范。
- 成员与邀请：分页、已加载成员筛选、邀请签发/重签/撤销、角色变更、停用/恢复和密码恢复链接。链接只在本次签发时显示，关闭后清除。
- 角色：活动/归档视图、按业务分组配置能力。勾选补齐必要能力，取消基础能力时取消依赖项；固定系统角色仅可查看。
- 设置：品牌信息与文件候选、类型限额、公开策略。未保存离开保护、修订冲突保留草稿；公开重开读取最新影响摘要并确认。
- 运行：任务分页和状态筛选、任务尝试详情与受控重试；审计精确动作筛选与详情；数据库、存储元数据、动效隔离和公开入口摘要。

正式入口沿用现有 API、修订、CSRF、权限与幂等合同；没有改动后端、数据库、部署或动效执行规则。读取前检查访问能力，服务端承担最终授权。再次确认身份后要求用户重新核对并提交，不自动重放治理操作。角色与邀请的新建弹窗在同次失败重试中复用幂等键。

## 浏览器证据

使用真实浏览器检查显式开发入口 `/demo/`；数据为中性合成，操作仅修改内存。视口为 1440×1000、390×844 和用户默认的 1221×1202。截图在第三批截图目录（本地 `../../apps/web/.impeccable/review/batch-3/`，不随版本分发）。

已完成的交互检查：

- 成员、邀请列表分别加载至 23 位、22 条，筛选控件与操作在手机可触达。
- 翻页失败后仍保留已加载的 20 位成员，显示读取失败并可重试。
- 生成演示邀请，得到保留 `/demo/` 基址的一次性交付链接；关闭后清除。
- 新建演示角色，选择下载能力会补齐查看素材能力；保存后新角色可见。
- 品牌草稿切换分类时出现站内确认，取消保留草稿；保存成功。
- 配置修订冲突显示错误，读取最新版本保留草稿，再次保存成功。
- 公开关闭与重开先确认，重开显示 12 份合成快照的影响摘要。
- 失败任务打开详情显示尝试记录；受控重试后状态为排队中，没有声称处理已完成。
- 审计详情、普通成员无权限状态、无凭据链接错误状态、再次确认身份弹窗可呈现和取消。
- 邀请与恢复入口之间切换会重新验证链接；初始化表单与未登录表单在两种尺寸检查。未输入或提交密码及初始化凭据。

视觉修正：手机成员操作栏的缩进不再造成横向溢出（390/390）；桌面角色弹窗宽度收至 820px，长表单使用固定操作区；管理说明与字段分区，手机采用纵向排列。键盘焦点可进入弹窗标题，主要表单控件有可访问名称，必要状态有文字说明。
