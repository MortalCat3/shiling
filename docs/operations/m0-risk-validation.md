## 3. T01-a 证据

### 3.1 PostgreSQL 与 pg-boss

在同一 `pg.Client` 事务中注入 pg-boss 的 `executeSql`：

- 业务行＋`boss.send` 提交后同时存在；回滚后二者同时不存在。
- 业务行＋`boss.complete` 回滚时业务行消失且 Job 保持 active；再次提交后二者同步完成。
- 停止进程后用新 pg-boss 进程可以取回此前已提交的待处理 Job。

这验证了当前版本所需的原子适配路径，和 [pg-boss transaction adapter](https://pgboss.io/api/adapters) 的接口相符；后续仍须用正式数据库访问层重跑 EN-01。

### 3.2 中文检索

12,004 行合成数据使用“规范化子串 AND＋结构化筛选”：

- “夏日＋果实”“蓝色＋3D”“晨雾”和标签精确过滤均返回预期素材。
- C.UTF-8 数据库中四字“流光交互”使用 GIN trigram 索引，单字“山”和双字“晨雾”走顺序扫描；本机约 4.7～5.3ms，只代表当前样例规模。
- `C` 区域下 `show_trgm('流光交互')` 为空，C.UTF-8 下可生成 trigram。

因此部署必须使用 UTF-8 且对中文有效的区域设置，并在干净安装中验证 `show_trgm`。首期不宣称语义搜索；一至二字查询必须在 D04 规模下复测。[PostgreSQL `pg_trgm`](https://www.postgresql.org/docs/18/pgtrgm.html)

### 3.3 Local 与图片

- 生成 3,152,409 字节、1024×1024 PNG，成功解码并生成 480×480 WebP；原件 SHA-256 未变化，证明无需旧 80 KB 门槛。
- JPEG 可解码；截断 PNG 和超过 4,000 万像素解码预算的 SVG 被拒绝。
- 对象键只接受服务端生成的 64 位十六进制摘要，路径穿越被拒绝；排他写入阻止覆盖。
- 完整流式读取返回 200，合法 Range 返回 206，非法 Range 返回 416；过期或资源绑定错误的短期授权返回 403。

## 5. T01-c MP4

合成文件为 MP4 容器、H.264 High/yuv420p、640×360、30fps、AAC-LC 48kHz 单声道、3 秒、约 380 KB。Chrome 返回 H.264/AAC `probably`，成功加载 3 秒元数据、拖动到 1.5 秒并继续播放；无媒体错误，服务端观察到 Range 请求。

该结果只建议将 H.264/AAC、yuv420p 作为首期播放输出基线。输入接受、直放还是转码、最大时长/像素/帧率、HDR/多音轨与资源限制必须用代表性 MP4 收口。

## 6. T01-d HTML/ZIP 与隔离

### 6.1 ZIP 结构

15/15 风险断言通过：正常包、边界体积、`../`、绝对路径、Windows 盘符、反斜杠、Unix 符号链接、重复/缺失/仅嵌套 `index.html`、条目数量、单项/总展开体积、压缩比和伪报展开大小均按预期接受或拒绝。实验阈值为 4 个条目、单项 1 KiB、总量 2 KiB、压缩比 20，只用于触发边界，不是生产默认。

结论是 ZIP 可以在不解压到不可信路径的前提下先枚举并受控拒绝；实际条目数、展开体积、字体/视频/WASM 及兼容范围仍须代表性包和部署预算。

### 6.2 浏览器来源与 CSP

两组来源对照各 12/12 指定断言通过：自包含 classic JS 可运行；`sandbox="allow-scripts"` 产生 opaque origin，脚本不能读取 `document.cookie` 或父页面 DOM，不能导航顶层；本轮测试的 fetch、图片和 beacon 没有到达接收服务。`sendBeacon()` 即使被 CSP 阻止也可能返回 true，验收必须检查 CSP violation 与服务端请求记录。

同时发现两个必须修正的架构边界：

1. **Cookie 不按端口隔离。** 主站与 iframe 只换端口时，iframe 首次导航仍携带普通和 HttpOnly 主站 cookie；使用 `localhost` 与 `127.0.0.1` 分主机对照才未携带。生产预览必须使用不匹配主站 Cookie 域的独立主机，并保持主站 cookie host-only。
2. **iframe 可以导航自身。** 包脚本成功将 iframe 自身导航到另一来源，请求到达接收端；当前 sandbox/CSP 不能证明所有出站通道被禁。服务端不可信执行必须另有网络命名空间/代理白名单、DNS 和云元数据阻断，不能靠 iframe 或 CSP 代替。

因此 `readyForUntrustedExecution=false`。当前只证明若干浏览器边界和可复现的负例；CPU、内存、进程数、磁盘、总时长、网络、DNS、云元数据、生产 TLS、ES modules/CORS、WebGL、音频及真实封面录制均未验证。T01-d 保持部分通过，不能放行无服务器隔离的新动效执行。
