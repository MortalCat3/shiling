# M0 后续所需媒体与部署信息

当前服务器部署请优先使用[部署配置总表与信息交接单](deployment-inputs.md)。下文保留 M0 阶段输入背景；已接入的原生阿里云 OSS、凭据文件交付和实际验收范围以 [OSS 运维](oss-storage.md)与[验收记录](oss-validation.md)为准。

- 状态：集中收集清单；不包含凭据
- 日期：2026-11-16

M0 已用中性合成样例验证基础链路，但真实格式范围、资源预算、S3 供应商行为和恢复目标必须由实际输入收口。下表区分最晚时点，避免把所有问题误设为 M1 的统一开工门槛。

## 1. 优先提供：对应媒体或存储实现前

| 类别          | 请提供                                                                                            | 用途与最晚时点                                   | 安全说明                                                                                     |
| ------------- | ------------------------------------------------------------------------------------------------- | ------------------------------------------------ | -------------------------------------------------------------------------------------------- |
| 图片          | 5～10 个可公开测试的代表性样例，或格式/最大文件大小/最大像素/是否包含透明、动画、HEIC、SVG 的说明 | T05 冻结输入格式、解码与预览预算前               | 可使用脱敏或可再分发样例；不要提供私人素材                                                   |
| MP4           | 3～5 个代表性样例，或编码、大小、时长、分辨率、横竖屏、帧率、音轨/HDR 情况；说明最大预期值        | T08 冻结直放/转码、超时与资源预算前              | 不知道编码时直接给样例即可，由 `ffprobe` 探测                                                |
| HTML/ZIP 动效 | 2～3 个代表性自包含包；说明是否使用 WebGL、WebAudio、字体、WASM、内嵌视频及是否需要鼠标/触屏交互  | T10 冻结包规范、隔离能力、录制预算前             | 不含外网依赖、构建脚本、账号、内部 URL 或秘密                                                |
| 目标客户端    | 必须支持的桌面/移动浏览器与最低版本；是否需要 iPhone/iPad/Android                                 | T08/T10 浏览器矩阵前                             | 若暂无要求，首期建议以当前 Chrome/Edge/Safari 和移动 Safari 的受支持版本为基线，再按样例实测 |
| S3 目标       | 实际供应商/兼容实现、region/endpoint、path-style 要求、测试 bucket/prefix、CORS/TLS/版本化情况    | T04 S3 实现与 T01-b 通过前；不阻塞 Local 图片 M1 | 凭据只在后续本地 `.env` 或秘密管理系统设置，**不要粘贴到聊天或文档**                         |

S3 测试权限至少需要在专用前缀内执行：创建/完成/终止分片、PUT 条件写入、HEAD/GET/Range、删除本轮测试对象。不能使用生产 bucket、历史素材或全桶管理权限。

请尽量给区间，不要求现在精确统计：

| 输入       | 可填写示例                                                      | 影响                             |
| ---------- | --------------------------------------------------------------- | -------------------------------- |
| 成员与并发 | 10～30 人；峰值 3 人上传、20 人浏览                             | 数据库连接、队列、限流与验收负载 |
| 素材规模   | 首年 5 万项／2 TB；月增 2,000 项／100 GB                        | 索引、分页、备份与容量告警       |
| 部署机器   | Linux x86_64/arm64；CPU、RAM、可用磁盘；是否可用 Docker/Compose | 图片/视频/浏览器执行并发与硬限制 |
| 存储偏好   | 首发 Local 或 S3；是否需要二者都在同一实例可切换                | M1/M2 实施顺序和运维说明         |
| 网络入口   | 团队站点域名、公开站点域名、独立预览来源、HTTPS/反向代理        | Cookie、CSP、CORS 与预览隔离     |
| 出网策略   | API/worker/preview 是否允许访问公网、DNS 或云元数据             | 动效执行器网络隔离与依赖下载策略 |

## 3. 运维目标：T04/T09/T12 前

| ID       | 需要确认                                               | 建议起点                                                                      | 影响                                  |
| -------- | ------------------------------------------------------ | ----------------------------------------------------------------------------- | ------------------------------------- |
| D05-a    | 撤回后，已签发公开下载/预览地址最多还能有效多久        | 公开下载与预览 grant 5 分钟；上传授权另按大文件传输设定                       | URL TTL、视频 Range、撤回文案与 FL-01 |
| D05-b    | 可接受的数据损失 RPO、恢复时间 RTO、备份保留和停机窗口 | 内部团队起点：RPO 24 小时、RTO 4 小时；至少保留 7 个日备份并异地/独立介质保存 | 备份频率、对象一致性、恢复演练和成本  |
| 恢复环境 | 备份保存位置、是否有独立恢复机器/存储、谁能执行恢复    | 至少能在不覆盖生产持久卷的隔离环境演练                                        | P03、升级回退和恢复证据               |

这些是建议起点，不是已经承诺的 SLA。P03 的恢复后安全行为已确认；D05-b 只负责数值目标。
