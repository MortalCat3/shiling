## 2. 路由、导航与入口

以下为前端页面路由，不是 API 路径。路径中的 ID 均为稳定业务标识；详情链接不包含存储路径、临时下载签名或权限令牌。

| 路由                              | 页面               | 可访问者与入口                                                                         |
| --------------------------------- | ------------------ | -------------------------------------------------------------------------------------- |
| `/`                               | 入口分流           | 已登录到素材库；未登录且公开入口启用到公开页，否则到登录页；首次初始化另按受控入口处理 |
| `/setup`                          | 首次初始化         | 仅未初始化实例＋有效一次性初始化凭据；完成后不再开放                                   |
| `/login`                          | 登录               | 游客；可接收校验后的同源站内 returnTo，不允许任意外部跳转                              |
| `/accept-invitation`              | 接受邀请           | 有效邀请持有者；令牌在 URL fragment 中消费后立即移除，不加入查询参数                   |
| `/recover-account`                | 设置新密码         | 有效恢复令牌持有者；不提供公开枚举账号或默认邮件找回流程                               |
| `/app/library`                    | 团队素材库         | 登录成员；默认 ready 且未归档素材                                                      |
| `/app/assets/:assetId`            | 团队素材详情       | 登录成员；是否可读取以服务端当前状态为准                                               |
| `/app/collections`                | 团队集合列表       | 登录成员；默认列团队active集合；归档视图只列本人或具governAny者有权治理的集合          |
| `/app/collections/:collectionId`  | 集合详情           | 登录成员；可检索集合中的可用素材                                                       |
| `/app/favorites`                  | 我的收藏           | 当前登录用户；不接受其他用户 ID 切换                                                   |
| `/app/uploads`                    | 我的上传任务       | 当前登录用户；批次、逐项处理、失败恢复                                                 |
| `/app/uploads/:batchId`           | 上传批次详情       | 批次 owner；管理员运维查看从任务管理入口进入并服从相同数据权限                         |
| `/app/archive`                    | 归档素材           | 成员默认本人；管理员可查看全部；不成为普通成员读取他人已归档原件的入口                 |
| `/app/admin/members`              | 成员与邀请         | 具备成员治理能力者，默认管理员                                                         |
| `/app/admin/roles`                | 角色与能力         | 具备角色治理能力者，默认管理员                                                         |
| `/app/admin/tags`                 | 标签字典           | 具备标签治理能力者，默认管理员                                                         |
| `/app/admin/settings/brand`       | 品牌               | 具备产品设置能力者                                                                     |
| `/app/admin/settings/types`       | 素材类型与业务限额 | 具备产品设置能力者                                                                     |
| `/app/admin/settings/publication` | 公开策略           | 具备产品设置能力者                                                                     |
| `/app/admin/tasks`                | 处理任务           | 具备任务治理能力者；查看阶段、受控错误、重试                                           |
| `/app/admin/audit`                | 必要审计           | 具备审计查看能力者；无全量原始日志或密钥展示                                           |
| `/app/admin/health`               | 系统状态           | 具备管理能力者；仅脱敏健康信息，不编辑数据库/云凭证                                    |
| `/public`                         | 公开素材库         | 公开入口启用时匿名可读；只查询公开投影                                                 |
| `/public/assets/:assetId`         | 公开素材详情       | 当前仍有效的公开版本；从内部详情复制公开链接也必须经过此页面的权限判定                 |

团队主导航固定为“素材库、集合、我的收藏、上传任务”；上传按钮为全局主操作。归档在素材库辅助入口，管理入口按能力显示。公开页面使用独立精简导航：品牌、公开搜索、登录；登录成员可见“进入团队空间”，不在公开页面混入团队上传/成员侧栏。

页面访问守卫用于正确导航，不能作为授权依据；API、媒体和下载入口仍检查权限。无登录访问团队地址进入登录页，登录成功回到原站内路径；无权资源展示“内容不可用或无权访问”，不通过差异文案泄露上传者、文件名或归档状态。

### 2.1 页面操作与26项能力的映射

文中“成员／管理员”描述默认角色行为，不能在页面里按角色名称硬编码按钮。页面根据服务端返回的当前资源 `actions` 显示动作；以下能力是其授权依据，能力本身仍须与所有权、状态、revision组合判断。自定义可信整理角色可以由sysadmin获得业务治理能力；只有 `system.*` 固定为sysadmin专属，始终不存在 `publishAny`。

| 页面动作                                       | 能力依据                                                                                                                                                      |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 团队浏览／下载                                 | `assets.read`、`assets.download`                                                                                                                              |
| 本人内部编辑／归档及恢复                       | `assets.editOwn`、`assets.archiveOwn`                                                                                                                         |
| 治理他人内部素材                               | `assets.governAny`；可委派可信角色，不产生发布权                                                                                                              |
| 创建／查看／取消／重试本人上传                 | `uploads.create`、`uploads.readOwn`、`uploads.cancelOwn`、`uploads.retryOwn`                                                                                  |
| 治理其他上传任务                               | `uploads.governAny`；可委派可信角色                                                                                                                           |
| 公开／更新本人快照／再次公开                   | `publications.publishOwn`；必须是owner                                                                                                                        |
| 撤回本人／任何公开                             | `publications.withdrawOwn`、`publications.withdrawAny`；后者可委派可信角色                                                                                    |
| 选用标签／治理字典                             | `tags.read`、`tags.manage`；挂标签还须素材编辑权；字典治理可授予可信角色                                                                                      |
| 集合读取／创建／维护本人／治理全部             | `collections.read`、`collections.create`、`collections.manageOwn`、`collections.governAny`                                                                    |
| 个人收藏                                       | `favorites.manageOwn`                                                                                                                                         |
| 系统成员／角色／设置／运行状态／任务／审计管理 | `system.members.manage`、`system.roles.manage`、`system.settings.manage`、`system.operations.read`、`system.jobs.manage`、`system.audit.read`；仅固定sysadmin |

成员只绑定一个roleId；固定sysadmin角色不可修改或删除。下文涉及管理员治理素材、集合、上传、撤回的操作，也适用于持有对应业务能力的受信任自定义角色；系统管理页面不因此向其开放。

## 3. 素材库：同一查询，网格与列表两种视图

页面从上到下是：搜索与上传入口 → 类型/标签/集合筛选 → 当前条件与结果状态 → 网格或整理列表 → 加载更多。网格用于发现灵感，列表用于比较信息和批量整理，两者共享筛选、排序和已选素材。

### 3.1 查询 URL 合同

示例：`/app/library?q=海报&typeId=image&tagId=tag_a&tagId=tag_b&collectionId=collection_a&sort=createdAtDesc&view=grid`。查询语义与03接口合同一致；`view`仅控制页面展示，不发送给素材查询API。

| 参数           | 语义与默认                                                                                                                             |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `q`            | 关键词；默认空；空白规范化，长度上限由共享合同提供                                                                                     |
| `typeId`       | 可重复的已注册类型ID，多个类型为OR；默认全部；停止该类型的新上传不从筛选中移除已有素材                                                 |
| `tagId`        | 仅团队页面使用，可重复的标签ID，去重；多个标签采用“同时包含”语义；不把可变标签名称当团队主键                                           |
| `tag`          | 仅公开页面使用，公开标签文本值，可重复且为AND语义；来自公开facets的label/value，不能用来反查团队tagId                                  |
| `collectionId` | 一个团队集合 ID；默认不限；在集合详情页由路由确定，不重复接受冲突参数                                                                  |
| `owner`        | 可选值 `me`，表示仅本人素材；默认全部；首期不提供任意用户身份选择器                                                                    |
| `state`        | 素材库默认active；归档页使用archived，仅返回本人或具治理权者可见范围                                                                   |
| `sort`         | 团队页为`createdAtDesc`、`updatedAtDesc`、`titleAsc`，默认createdAtDesc；公开页为`publishedAtDesc`、`titleAsc`；每种排序都有稳定ID次序 |
| `view`         | `grid`或`list`；默认grid；不改变数据范围                                                                                               |

个人收藏页隐含当前用户收藏范围（API的favorite=true）；集合页隐含对应集合范围，仍可用关键词、类型和标签缩小结果。公开页只支持公开关键词、类型、公开标签、排序和视图，不接受团队集合、owner或归档条件。公开状态首期在详情和整理列表展示，不另做与接口不一致的前端本地筛选。

查询参数白名单校验；无效值给出可恢复提示并回到有效默认，不触发错误循环。中文输入法组合输入结束后再查询；普通输入采用短防抖。显式筛选操作写入历史，连续搜索输入替换当前搜索项，避免浏览器返回键逐字回退。

游标仅属于当前查询的加载状态，不固化为长期分享参数。页面刷新恢复条件并加载首批；同一会话从详情返回恢复此前已加载结果和滚动位置。切换查询取消旧请求，迟到结果不得覆盖新条件；统计加载失败不能阻止已有素材浏览。

### 3.2 卡片、列表与预览

- 默认卡片按 v0.2 展示原比例封面与小标题，必要类型/播放提示和收藏/下载动作轻量呈现；格式、标签和“仅团队／已公开”等详细信息进入整理列表与详情，不堆在默认封面下方。处理中上传不混入默认素材库。
- 整理列表增加格式、尺寸/时长、文件大小、更新时间等列；移动端采用紧凑信息行，不强迫横向显示全部桌面列。
- 图片优先受限缩略图；MP4与动效默认封面，主动操作或设备适合时悬停播放短预览。全局限制同时激活的媒体数量；离屏、切后台、打开详情时停止不必要预览。
- 减少动态效果偏好下默认静态封面，用户仍可显式打开详情播放；触屏没有悬停，使用明确播放入口。
- 列表加载失败提供重试，不把失败渲染成“没有素材”；无结果展示当前条件与“清除筛选”；空库展示上传入口。

## 4. 详情深链、弹窗与编辑

### 4.1 一条详情地址，多种容器

视觉基准：[原型 v0.2](../prototypes/v0.2/README.md) 的方向已确认，桌面从列表打开采用居中双栏弹窗。详情深链、焦点、返回位置与独立访问规则不变，实际检查见[原型落地与体验验收](05-prototype-acceptance.md)。

从桌面素材库打开时，地址变为 `/app/assets/:assetId`，在保留列表背景的居中双栏弹窗中展示；关闭或浏览器返回恢复原列表条件、已加载内容与滚动位置。移动端同一路由展示独立全屏页面。直接访问或刷新详情地址时展示独立详情页，没有列表背景也能使用，不依赖内存中的上一页面。

从列表打开的来源上下文仅在同一浏览器导航会话中使用；复制详情链接只复制规范详情地址，不复制内部筛选词、签名文件地址或一次性凭据。直接进入详情的“返回素材库”使用默认素材库；不得误执行一次未知外部历史返回。

桌面详情采用“左侧预览区＋右侧信息/操作区”的已确认布局；移动全屏的排列、尺寸和断点按可用性检查落实。打开后焦点进入详情标题或首要可用操作，关闭后回到原触发项；原项已被移除时回到结果区域标题。弹窗不叠加第二个完整详情层；公开/编辑表单的承载需保留来源上下文并补齐未保存反馈。

### 4.2 三类预览与使用

| 类型         | 预览与必要信息                                               | 主动作及失败回退                                                                           |
| ------------ | ------------------------------------------------------------ | ------------------------------------------------------------------------------------------ |
| 图片         | 适配画布、1:1、缩放；尺寸、格式、大小；默认用预览衍生图      | 下载原图；预览失败可重试，有权限且原件完整时仍可下载，不以图片加载失败推断资产丢失         |
| MP4          | 播放、拖动、静音、倍速、全屏；时长、分辨率、源格式           | 下载原视频；播放不兼容显示明确原因，不给空白黑屏；前后台切换不自动有声播放                 |
| HTML/ZIP动效 | 独立来源内交互；封面、约定短循环；控制项依处理器验证能力显示 | 下载源HTML或源ZIP；交互失败保留封面与允许的源文件下载，提供重试；不显示没有实现的倍速/暂停 |

详情中“复制团队链接”始终可用于团队协作；存在有效公开时另提供“查看公开页”“复制公开链接”。两者清晰区分。不能因为复制了链接便创建公开记录。

### 4.3 元数据编辑

本人或具有治理权限者可编辑内部标题、说明、标签；原件/类型/版本不在首期编辑表单中。成员从已有标签中选择，标签管理员可从治理入口创建标签。表单显示当前revision，提交时服务端检查冲突。

公开素材编辑内部信息后提示“团队信息已保存，公开页面仍使用此前快照”；不自动更新公开标题、说明或标签。owner可选择“更新公开信息”，治理者编辑他人内部信息后不能借此替其更新公开快照。

未保存内容离开表单时提供“继续编辑／放弃修改”；保存失败保留输入。PATCH保存使用If-Match，过期返回412；界面展示“素材已被更新”，允许载入最新内容并对照重填，不提供无条件覆盖他人修改的按钮。登录过期可在同一页面重新登录后恢复表单；敏感输入不默认持久化到跨账号localStorage。

## 5. 上传批次与任务工作区

### 5.1 创建批次

点击上传或拖入文件后进入上传工作区；不先强制选择类型。图片和MP4每个文件形成一个上传项，HTML单文件和ZIP动效包各形成一个上传项；ZIP内文件不会拆成多份素材。

发送前列出文件名、识别类型、大小和允许范围；类型以服务端真实内容核验为准，扩展名与浏览器MIME只是预检线索。显示“处理合格后团队成员可见；公开需要另外操作”。标题默认使用去掉扩展名的文件名，可修改；标签与集合可暂不填写。

批次创建后获得稳定地址，逐项独立进行；页面显示“总计／可用／处理中／失败／取消”。批次聚合状态不替代逐项状态。最多并发、大小与数量从实例能力配置读取，不沿用旧系统20MiB或80KB等限制，也不在视觉文案中硬编码另一套值。

### 5.2 逐项状态及操作

以下是用户可见状态；与领域/API中的规范枚举保持映射，不额外持久化一套UI状态机。

| 可见状态             | 含义                                                                                                   | 可执行操作                                                                        |
| -------------------- | ------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------- |
| 待上传               | 已排入批次，尚未发完文件                                                                               | 开始/自动排队、取消                                                               |
| 上传中               | 客户端正在传输文件                                                                                     | 看进度、取消；不显示“已保存”冒充服务端完整接收                                    |
| 传输中断             | 网络/会话/页面中断，服务端仍可确认上传进度                                                             | 重新登录、重试当前文件；需要本地源文件时明确要求重新选择同一文件                  |
| 校验中               | 服务端检查完整性、大小与格式                                                                           | 查看状态、请求取消                                                                |
| 等待处理             | 文件已接收，等待worker                                                                                 | 可离开页面；查看队列状态、请求取消                                                |
| 处理中               | 解码、转码、封面或动效检查等                                                                           | 查看阶段、可离开页面、请求取消；进度未知时显示阶段，不伪造百分比                  |
| 团队可用             | ready提交成功，已进入团队库                                                                            | 打开详情、补信息、加入集合、公开本人素材、归档；不再出现“取消上传”                |
| 失败                 | 某步骤失败，其他上传项仍可继续                                                                         | 查看可操作原因；允许时重试同一步；输入无效则重新选择修正后的文件新建上传项        |
| 失败：上传权限已撤销 | 账号被禁用或失去uploads.create，未ready的提交被阻止；规范状态仍为failed，错误码为AUTHORIZATION_REVOKED | 恢复账号及所需上传能力后手动重试；不增加blocked持久状态，不因重新登录自动继续入库 |
| 取消中               | 服务端已接收取消请求，等待确认最终结果                                                                 | 暂停重复操作，继续查看；不提前从批次移除                                          |
| 已取消               | 未入库项已终止，迟到产物不会成为ready                                                                  | 可新建上传；不向用户承诺文件此刻已物理清理                                        |
| 已过期               | 未完成上传超过已公布的接收/恢复时限，原上传项不再接受提交                                              | 新建上传项；不把expired改回uploading，不以过期草稿时限影响已经ready的素材         |

可重试的系统故障与不可原样重试的输入错误必须区分。格式/包结构不支持、超限、检测未通过不提供无限“重试同一内容”；对象完整存在但后处理失败优先复用原上传结果，不让用户再次传输大文件。

### 5.3 取消、断线和结果不确定

- 取消单项只作用于该项；“取消未完成项”先展示数量，不影响已经ready的素材。
- 取消请求与ready提交竞争时，以服务端结果为准。若ready已成功，取消返回冲突，提示“素材已进入团队库，可前往归档”；不把已入库素材静默删除或偷偷归档。
- 离开上传页不等于取消。文件还在客户端传输时提示离开可能中断；文件已完成服务端接收后，后台处理不依赖页面保持打开。
- 本地存储模式允许单文件重传；经验证的S3分片上传可恢复已成功分片。界面根据实际能力说明，不能统一承诺浏览器关闭后继续上传。
- 重新打开任务页先获取服务端状态，再决定是否需要重新选择文件。重新选择时验证大小/摘要等绑定，内容不同应创建新上传项，不能覆盖旧原件。
- 请求超时不能直接判定操作失败。提交、重试和取消均用原操作身份查询/重试，避免用户点击后产生重复素材；在结果未确定时展示“正在确认结果”。
- 账号切换清空前一用户的批次、输入与缓存。普通成员不能通过替换batchId查看他人上传内容；管理员运维入口可见范围遵循权限设计。
- 即使文件已上传或媒体处理已接近完成，ready提交前仍要核对owner账号有效及uploads.create能力。失效则显示failed＋AUTHORIZATION_REVOKED；停用期间用户不能继续访问私有任务，重新启用后才可查看原因并手动重试。管理员重试也不能绕过owner尚未恢复的入库资格。

### 5.4 重复文件提示

重复检测仅为提示，不产生阻塞状态。核验发现重复后，本次上传仍按正常流程处理并入库为独立逻辑Asset，owner保持本次上传者；首期不做全局物理去重、不自动关联他人Asset、不转移owner或合并元数据。

界面提示“团队中已有相同内容，本次入库将继续”，仅展示当前用户有权访问的素材摘要。用户可打开已有素材并收藏/加入本人可维护集合；若不需要本次新副本，可取消尚未完成的上传项，已经ready则归档新素材。不得展示无权访问素材的标题、owner或路径；不提供需要再确认才能继续的“重复待处理”状态，不作“秒传”承诺。相似图识别后置。

## 6. 标签、团队集合、个人收藏与批量操作

### 6.1 团队集合

集合列表显示名称、说明、当前可用素材数量；团队成员可创建集合，只有集合创建者或管理员可改名、改说明、增删条目。可把任何团队ready未归档素材放入自己有权维护的集合；这不会授予该素材标签、公开或归档权限。

集合详情沿用素材库网格/列表与筛选。未归档且有权限的条目正常显示；素材归档后从正常集合视图隐藏，但保留关联，恢复后重新出现。集合数量只计算当前可用项，避免数量与列表不一致。集合不能整体公开，也不作为授权容器。

成员从他人集合点击“加入集合”只能选择自己可维护的集合；原集合没有编辑入口。首期支持集合归档与恢复，不提供永久删除：集合owner＋manageOwn或governAny者可执行，采用集合expectedRevision并原子修改集合状态。

集合归档只从正常集合导航和选择器移除集合，保留所有条目关系，不归档、删除或撤回其中素材；归档集合详情仅owner/governAny可见并提供恢复。归档期间不接受增删条目和常规元数据修改，避免隐藏的整理结果；恢复后重新展示当前可见的条目，不公开任何素材。集合归档页与素材归档页分别命名，确认框明确它们影响的对象不同。

### 6.2 个人收藏

收藏是当前用户与素材的一条偏好关系，可在卡片、详情及批量工具中切换。不创建收藏夹层级。取消收藏只移除个人关系，不影响素材或团队集合；素材归档时正常收藏列表隐藏该项，恢复后按原收藏关系恢复。

游客点击收藏提示登录，不为游客创建服务器收藏或后台导入队列；本次无旧浏览器收藏迁移。登录后重放的收藏动作只针对原稳定assetId并重新授权，不能盲用登录前缓存对象。

### 6.3 标签字典

以下按已确认 D02 设计。成员可查询和选择既有标签；具备tags.manage者可创建、改名、停用和恢复标签，名称重复与规范化规则由共享合同统一。首期不提供标签合并、层级标签或隐式自动改名。停用默认仅禁止新增绑定，已有素材仍保留该标签的可读显示和筛选能力，避免历史条件失效。恢复发生名称冲突时明确提示，不静默合并。

公开标签是Publication快照的文本字段，不随内部标签改名或停用自动修改；公开表单只能从Asset当前已关联标签中显式选择子集。普通成员不能通过上传或公开表单提交陌生标签ID/新字符串绕过标签治理权限。公开facets仅返回快照中的label/value及count，不输出团队tagId。

### 6.4 批量操作的共同规则

| 操作               | 权限与结果                                                           |
| ------------------ | -------------------------------------------------------------------- |
| 加入／移出个人收藏 | 只改当前用户的偏好；对当前可用素材执行                               |
| 添加／移除标签     | 仅本人素材或具备治理权限的素材；首期不提供“一键替换全部标签”         |
| 加入／移出集合     | 先检查集合维护权，再检查每个素材团队可用状态；不要求操作者拥有该素材 |
| 归档               | 本人素材或管理员可治理素材；提示其中多少素材已公开，归档会同步撤回   |
| 恢复               | 本人归档素材或管理员可治理素材；恢复为团队可用，不自动公开           |
| 公开／更新公开     | 首期不做批量公开；每项需检查公开快照表单，避免跳过字段确认           |

选择只针对显式勾选ID；“全选”只选择当前已加载结果，文案显示实际数量，不悄悄选择整个搜索结果。切换筛选范围会清空选择并提示；切换网格/列表不清空。首期不做基于未来查询结果的后台“全库操作”。

提交前展示“可处理N项、无权限或状态不符M项”，用户确认明确的ID范围；不得偷偷扩大或省略影响。素材批量标签/归档/恢复按项显示成功、失败及原因；重试仅针对可重试失败项。单一集合的一批条目增删按集合revision原子提交，全部成功或全部不变，不能显示部分成功；冲突后重新获取集合再确认。批量收藏由若干幂等关系操作组成，按项反馈。后端仍核验当前权限与状态，前端预检结果不是授权凭证。

## 7. 显式公开、公开快照与撤回

### 7.1 公开入口与表单

仅asset owner且拥有publishOwn、素材ready且未归档时显示“公开素材”。管理员查看他人素材没有该按钮；不可通过管理员路由、批量动作或修改owner来绕过。实例未启用公开入口时显示管理员配置状态，不让普通成员提交一个注定不可访问的公开结果。

表单标题是“公开素材”，固定提示“公开后，无需登录即可查看并下载这份内容”。首期采用下列公开字段白名单：

| 字段                                                       | 表单行为                                                                                                |
| ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| 内容版本与下载文件                                         | 只读，显示本次ready版本及类型/格式/大小；不能选择未完成版本，也不能把替换原件藏在此表单                 |
| 公开标题                                                   | 必填；可从内部标题预填，必须能编辑和预览                                                                |
| 公开说明                                                   | 可选；默认空，用户明确选择复制内部说明后才加入快照                                                      |
| 公开标签                                                   | 可选；仅从当前Asset已关联标签中显式选取子集，默认不全选；不可直接添加尚未关联的字典标签或自由输入新标签 |
| 封面与播放/交互预览                                        | 展示将公开的预览；衍生物由处理器产生，首期不提供任意外链封面或嵌入脚本                                  |
| 姓名、头像、上传者账户、成员ID、团队成员字段               | 不提供字段，不从账户自动带出，不进入公开响应或页面                                                      |
| 内部集合、内部备注、处理错误、对象存储位置、原始上传文件名 | 不提供字段，不公开；下载使用系统生成的中性文件名，不从账户或原始文件名推导                              |

来源与许可证属于内容来源信息，不能等同于成员署名；是否增加独立公开来源字段留后续明确，首期不把内部source/author字段整块透传。用户在说明中主动输入的普通文字由表单预览显示，系统不推导或补全成员身份。

公开表单提交的publicMetadata字段为title、description、tagIds；服务端核验tagIds属于Asset当前关联集合的子集，再保存publicTags字符串快照。公开页面、公开详情和公开搜索只使用该文本快照，不返回team tagId，不从字典读取最新名称覆盖旧快照。

提交前提供实际公开快照预览；“确认公开”是单次明确动作，不再增加审批流程。提交绑定asset/version/revision与操作身份，按钮防重仅改善交互；服务端保证幂等。成功后显示“已公开”，提供查看公开页和复制公开链接。

### 7.2 已公开信息更新

公开详情始终读取最后一次成功提交的公开快照。内部标题、说明、标签变化不自动同步。owner看到“内部信息与公开信息不同”后可进入“更新公开信息”，对照当前公开字段与准备提交字段；同样需要明确确认。

治理者修改他人的内部素材时，只能看到公开状态与获授权的“撤回公开”治理动作，不能保存新的他人公开快照。公开更新冲突时保留用户输入并重新读取当前快照；不以最后一次写入静默覆盖另一页面的修改。

### 7.3 撤回

owner可撤回自己的公开；管理员可撤回任何公开。确认框说明：新的公开访问与下载授权将停止，团队内部内容保留；已发出的短时文件地址会在已配置窗口内失效，已下载副本无法收回。确认成功后公开状态为“已撤回”，不是删除素材。

公开链接继续使用规范assetId路径，但撤回状态下游客获得统一“内容不可用”页面，不展示原公开标题、owner、团队状态或“其实已转私密”等存在性提示。再次公开须由owner重新确认快照；管理员不能通过恢复归档自动重新公开。

## 8. 归档与恢复

素材库和详情中的“归档”仅对owner或具备治理权限者显示。确认内容包括资产数量、会从团队正常浏览/搜索隐藏、存在公开时会撤回；不是原文件物理删除。批量归档逐项返回结果。

归档页成员只看本人，具governAny者可筛其治理范围；支持关键词、类型和接口约定排序。归档详情向owner/governAny展示受控元数据、归档原因/时间、必要的安全静态预览与恢复动作。静态预览只使用已核验缩略图或封面，不提供原件下载、MP4播放、动态短循环或主动动效执行；需要这些使用能力必须先恢复。静态预览仍重新核验当前归档读取权限，不复用公开grant。

恢复成功后回到团队可用状态，原标签、集合关联、个人收藏关系可重新生效；公开保持撤回，需owner另外公开。恢复失败保留归档状态并说明原因，不能显示“已恢复”但文件仍不可用。

用户已明确首期无素材永久删除：归档页无“清空回收站／彻底删除”，也不通过保留天数自动清理归档资产。未完成上传和无人引用临时产物的运维清理是不同对象，不能借此删除已归档Asset原件。

## 9. 成员、角色、设置与管理

### 9.1 成员与邀请

成员页显示团队内部账号、显示名、状态、角色及必要管理动作；这些字段不进入公开产品响应。管理员创建邀请时可预留账号并选择角色：预留后接受页只读；未预留时由受邀者在接受事务中填写唯一账号。成功后只在当前授权界面显示一次邀请链接与有效期；复制失败提供手动选择。关闭后不重新显示原令牌，只能显式撤销/重签并废止旧令牌。

停用成员前明确告知会使其后续会话和操作失效，尚未ready的上传也会停止提交并以failed＋AUTHORIZATION_REVOKED保存；恢复账号及uploads.create后需手动重试，不自动入库。不自动撤回其历史公开，由具权限者另行治理。角色变更预览新增/移除能力与受影响人数，移除uploads.create具有相同入库阻止效果；最后有效管理员保护由服务端原子检查，前端确认不能代替约束。编辑自身角色导致失权时，成功后重新获取能力并离开已失去权限的页面。

### 9.2 角色

角色编辑器使用固定能力目录，显示“本人／全部”等范围说明，不接受自定义脚本或布尔表达式。本实例成员模板包含publishOwn；管理员模板治理全部素材与撤回公开，但不含发布他人素材或更新他人公开快照的能力。

角色重命名不改变稳定ID。已分配角色不能直接删除导致成员无合法权限；首期禁用此操作并引导先调整成员分配。游客不是可被改造成上传者的普通角色，公开读权限始终受Publication和实例公开开关约束。安全验证、来源隔离和原件保护不在可勾选权限内。

### 9.3 产品设置与运行状态

修改业务限额不自动取消已受理任务或删除已存在文件；安全隔离条件失效可以阻止执行并给出明确原因。停止动效交互能力可保留安全封面和有权限的源包下载，但当前实例三类型完整MVP验收仍需动效处理与预览工作。

**D01公开总开关（已确认，待实现与验收）**：关闭不逐条撤回 Publication；重新开启恢复仍符合 active、未归档、未撤回等条件的快照，并不重新发布任何未公开素材。重开前刷新管理设置接口的 `publicationImpact`，展示 `eligibleActiveCount` 与 `evaluatedAt`；摘要失败不能当作 0，设置 revision 变化后重新确认。数量是读取时点值，不锁定素材集合，提交仍按当时资格判定。开关改变授权 epoch，旧 grant 不会复活；已签发第三方存储 URL 仍受其有限 TTL 约束。

## 10. 公开游客页面

公开首页独立加载公开投影，默认显示当前有效公开快照；任何标签计数、搜索结果数量和推荐项只能由公开内容计算，不泄露团队总量。公开页不包含团队集合筛选、上传者筛选、成员头像、用户名、账号、个人主页入口或内部状态。

游客打开公开详情即可预览和下载，无需登录。下载前服务端再次核验公开资格；下载地址过期时允许获取新的短时授权，不能要求游客“登录解决”已公开内容的正常过期。公开被撤回时停止重试下载并显示统一不可用状态。

登录入口仅用于团队访问和个人收藏；登录成功保留原公开详情上下文。收藏操作需要团队登录身份且资产仍可访问，不能让公开浏览强制依赖账户。公开链接复制不创建token、不延长权限、不覆盖撤回策略。

公开功能关闭时显示实例级不可用页面，不列出原公开素材或内部原因；不存在/撤回的单个素材使用统一不可用页面。公开页面错误不回显存储bucket、内部域名、成员标识或处理日志。

## 11. 初始化、登录、邀请与账号恢复

### 11.1 首次初始化

运维准备部署配置并启动服务后，以一次性受控凭据进入setup。未持有凭据者仅看到“实例尚未完成初始化，请联系部署者”，不能通过抢先打开网页成为管理员。多个初始化请求竞争时仅一个成功。

初始化入口只原子创建首个管理员，成功后立即关闭并进入登录。登录后在受保护的设置引导中完成名称与基础品牌 → 选择预设并检查实际差异 → 确认类型与公开策略 → 健康检查 → 进入空素材库。后续配置失败不把实例倒退成“未初始化”，超时先查 `GET /bootstrap`，不得再次创建管理员。可跳过邀请；不要求先接入邮件、SSO、AI或外部云服务。

预设只是配置初值，同一数据模型与页面；任一预设均不自动公开上传内容。通用发行版默认关闭匿名入口；本实例按已确认规则启用公开入口并向全员授予publishOwn。初始化完成后setup及初始化凭据失效，不能通过清cookie重来。

### 11.2 登录

账号密码提交后读取服务端principal与能力；登录失败不区分账号不存在/密码错误来枚举成员。界面提供密码显示切换和明确等待状态；失败不清空账号但清理不应长期保留的密码。限流时显示合理等待提示，不在前端绕过或自动密集重试。

登录成功返回经过白名单校验的站内路径；登录前待收藏可重新授权后重放，公开、归档、成员治理等修改动作只恢复表单，不自动提交。退出清除用户相关缓存、私有页面数据和待操作意图；浏览器返回不应展示前一用户的受限数据。

### 11.3 接受邀请

邀请链接在fragment中携带一次性令牌；页面读取后立即从地址移除，只在当前流程内存中保留。页面显示经令牌验证后的角色摘要；已预留账号只读，未预留时允许填写符合合同的唯一账号。角色不能修改。刷新导致内存令牌丢失时提示重新打开原链接，不把令牌写入持久存储补救。

邀请无效、过期、已使用或已撤销时使用同类不可用提示并引导联系管理员，不暴露成员列表。接受成功清理令牌并进入登录页，用户使用新密码登录；不默认在接受邀请时沿用另一个已登录账号的会话。发现当前已登录不同账号时先明确身份冲突，由用户退出后接受。

### 11.4 无邮件账号恢复

登录页“无法登录”解释本实例恢复方式：联系管理员；首期不发送无配置邮件、不提供可枚举账号的公开重置接口。管理员在成员页发起恢复，生成一次性短时恢复链接，通过已确认的渠道交给用户；应用不擅自向外部发送消息。

持有恢复令牌者进入recover-account设置新密码；成功后旧会话及该恢复令牌失效，返回登录。恢复不能激活已停用成员或更改其角色；停用恢复是管理员独立操作。唯一管理员失去密码时使用受控本机运维恢复流程，网页不提供后门账号或默认密码。

## 12. 跨页面体验与关键验收
