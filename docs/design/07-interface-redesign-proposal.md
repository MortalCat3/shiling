# 核心界面重构：调研、范围与方向评审

- 日期：2026-11-16
- 状态：用户已确认 B「创作工作台」、第一、二、三批范围和桌面双栏详情；实现与验收另记。
- 对象：现有拾灵工程的 `apps/web` 与真正通用的 UI 边界；不新建仓库或工作树，不修改数据库和后端。
- 已再次确认：面向创作团队日常使用；找灵感与找可用素材同等重要；确认方向后直接制作可运行前端，再检查视觉与交互。
- 新授权见 [ADR 0005](../adr/0005-interface-redesign-scope.md)，产品事实见 [PRODUCT.md](../../PRODUCT.md)。

## 1. 结论

建议以「创作工作台」为首期方向：让素材占据主要屏幕，使用轻量导航和稳定的搜索/筛选工具条；浏览网格与整理列表共享内容、查询、选择和详情。辨识度来自精确的版式、密度、内容构图和状态表达，而非在每个页面增加装饰。

先交付一条完整可运行主线：素材库 → 搜索/筛选 → 详情/下载 → 上传/处理反馈 → 重新找到素材。其后扩展整理、公开与管理。完整首期范围保留，但不一次性重做所有页面。

本轮是对新平台现状的调研，不是旧平台审计或全量业务验收。当前可以使用合成素材展示状态；模拟公开、处理成功和下载不能被计为真实后端验收。

## 4. 关键流程设计

### 浏览与取用

进入素材库 → 看当前范围/最近上传 → 输入关键词或组合筛选 → 网格判断视觉、列表判断规格 → 打开详情 → 下载原件/收藏。返回保留筛选、已加载项、滚动与触发点焦点。

搜索当前收藏/集合时保留上下文，显式切到全库时才改变范围。所有已生效筛选可单独移除；列表与网格切换不清空选择。长标签收进“更多标签”选择器，不把整本字典铺在首屏。

### 上传与失败恢复

选择多个文件 → 展示可接收类型、实际配置限额与团队可见提醒 → 逐项传输 → 校验/等待处理/处理中 → 团队可用。百分比只对应可测传输；处理只呈现阶段。部分失败可只重试失败项，错误解释为“发生了什么、能否修正、下一步做什么”。

有任务时将投放区压缩为工具条；历史批次显示日期、文件数和失败/进行中状态。离开页面区分本地传输与服务器处理。模拟处理使用显式演示模式，不驱动真实 worker、不改库。

### 批量整理

进入选择 → 勾选/选择已加载 → 显示可处理与不可处理数量 → 选择单一动作 → 查看逐项结果。成功项更新，失败项保留名称、原因和可重试状态。更换查询范围清空选择并说明；视图切换保留选择。

素材标签/归档/恢复按项反馈；同一集合条目批次全成或全不变，失败提示明确。归档页仅恢复等合法动作，不提供不适用的标签或加入集合操作。

### 公开与内部编辑

内部详情 → 公开信息区域 → 核对公开标题、说明、所选标签及原件交付 → 确认公开 → 查看/复制公开链接。内部编辑成功后明确“团队信息已更新，公开信息未变”。更新公开采用前后对照；取消不改快照。治理者只有获准撤回入口。

保留桌面双栏详情作为推荐的容器；编辑/公开在同一详情内切换信息面板，避免叠加多个完整详情弹窗。长表单移动端使用独立全屏并固定合法主动作。

## 5. 三个视觉方向

三种方案共享业务规则，区别包括导航布局、密度、字体节奏、色彩面积和交互方式。示意只供评审，不是已实现界面。下列色值和尺寸是方向描述，不是已确认 token。

### A · 展览导视

**主张：像进入设计展览一样快速辨认内容区，但每个区域都可直接操作。**

- 参考世界：展览导视与作品墙。白色内容场、朱红导航面、黑色文字；非装饰性的大范围标识，让当前范围容易定位。
- 布局：窄导航轨＋上方清晰的页名/搜索/上传；类型、标签、集合在一条横向工具带。桌面约四列大图，原比例展示，内容区不出现欢迎横幅和统计卡。
- 字体：中文无衬线，页名约 28px/较重；正文 14–15px，紧凑标签与细线分区；不引入装饰宋体。控件小圆角，图片保留克制圆角。
- 交互：当前范围像导视牌持续可见；选择后同一位置转换成操作带，批量结果保留状态。详情仍可用双栏，公开页移除团队轨道。
- 手机：带文字的主入口与单层导航抽屉；工具带折成有计数的筛选按钮，图片两列，列表一列；不依赖图标猜入口。
- 跨页面：上传按阶段分区，集合用作品拼贴，管理用明确分区表单；错误用独立状态符号与文字，避免品牌朱红和危险状态混淆。
- 价值：三案中识别度最强，公开页也有完整品牌感。风险：导航色块可能争夺素材注意力；色彩丰富的素材需要更大的中性隔离区。
- 相对成本：中；导航与标题体系改动较多。

从挑战方向吸收的纪律：机场导视的“每个决策点只给相关动作”；竖屏媒体流的“内容占主要面积”；高密度网站的“信息可见而非一律藏起来”；票券的“取消状态不消失”；网格字样的“布局与控件使用同一网格”。不复制机场、票券或像素字装饰。

### B · 创作工作台（推荐）

**主张：像看选片台一样扫图，像整理工作目录一样精确操作。**

- 参考世界：摄影选片接触表与创作工具的工作区。近白画布 `#FAFAF8`、中性浅灰 `#ECEDEA`、墨黑 `#202320`、深蓝 `#244BC5`；蓝色只承担主动作、选择和焦点。
- 布局：约 200px 文字侧栏；紧凑顶栏显示当前范围、搜索、上传；下方一行类型/筛选/排序/视图。桌面默认约五列中等图，间隔 12–16px；整理视图转为对齐信息行。
- 字体：系统中文无衬线为主体，14px 控件、24px 页面标题；数字用等宽数字，层级由字重、留白、对齐形成。4–8px 控件圆角、约 8–10px 图片圆角，浮层使用轻阴影。
- 交互：持续保留查询上下文；卡片主点击打开预览，轻量收藏/更多入口可见；进入选择后固定操作栏承载动作和逐项结果。详情保留大预览与窄信息栏。
- 手机：顶部展示页面范围与搜索，常用入口带文字；筛选抽屉、两列图片、一列集合和任务；详情全屏，下载/保存操作不被软键盘或长内容遮挡。
- 跨页面：集合用真实素材缩略图组合而非空文件夹；上传先看任务再补信息；公开页扩大内容宽度；管理复用同一控件与反馈体系。
- 价值：最均衡地支持浏览与取用，开源部署者换品牌也不破坏界面。风险：结构与成熟素材工具较接近，辨识度必须由选片节奏、精细排版和交互完成度建立；不是仅换蓝色。
- 相对成本：中；保留路由与详情逻辑的价值最大，集中投入共享组件和状态。

### C · 媒体调度台

**主张：把素材和处理任务呈现在一块稳定、可扫描的调度板上。**

- 参考世界：固定列、按行更新的车站信息板，转译为媒体工具，不制作列车拟物界面。
- 色彩：石墨黑 `#171B1E`、深灰 `#252B30`、白灰 `#F0F2F3`、琥珀 `#F2B24B`；琥珀用于当前操作和等待，错误独立红色且配文字。
- 布局：约 160px 紧凑侧栏；上方搜索与范围；首屏以有缩略图的高密度列表为主，右侧保留约 320px 预览检查区；可切多列图片接触表。动作靠近当前行，信息列保持稳定。
- 字体：中文常规黑体保证可读性，英文类型/数字紧凑排列；正文 14px、辅助 12px，不复制参考图的极窄中文或巨大宣传字。
- 交互：上下行浏览、预览随选择更新，完整详情仍有稳定地址。任务变化只更新相关行，不重新排列用户正在操作的区域；不做逐字翻牌装饰。
- 手机：取消常驻右栏，行项目保留预览/名称/状态/主动作，其余进入全屏详情；reduced-motion 直接替换状态。
- 跨页面：上传与治理最有优势；公开页减少工具感，仍使用同一深色媒体背景。主库保留网格入口以支持找灵感。
- 价值：信息密度和视频查看体验突出，状态差异明显。风险：日间阅读、深色素材与色彩判断需额外验证；主库默认列表偏向管理；常驻检查器改变既有详情使用方式。
- 相对成本：中到高；需要管理列表/检查器焦点和键盘联动，并为暗色主题做完整对比度与媒体底色验证。

参考仅作为工艺与状态系统对照：[调度板参考](https://impeccable.style/worlds/cards/signals-instruments-split-flap-concourse.webp)、[首屏参考](https://impeccable.style/worlds/cards/signals-instruments-split-flap-concourse-hero.webp)。其中文案、统计、纹理与宣传布局不属于拾灵需求，也不会复制成产品页面。

### 方向选择说明

推荐 B；A 适合更强品牌表达，C 适合明显偏视频与集中整理的工作习惯。也可以要求重新探索、更克制或更鲜明，或者明确选择成熟素材工具的常规布局。无需在本轮逐项选 CSS 数值。

## 7. 内容、配置与验证策略

### 演示内容

制作原创或许可明确的中性图片、可播放合成 MP4，覆盖横/竖/方/长图、长标题、多标签和极端文件描述。动效只展示明确的禁用、等待或安全静态状态，不执行上传包、不用假封面声称 ready。

演示数据按页面需要形成固定情景：空库、正常内容、加载中、网络失败、权限变化、公开差异、部分批量失败、处理失败、归档与恢复。建议使用约 24～40 条合成素材验证密度与翻页；该数量是 UI fixture，不代表真实容量或后端分页参数。

默认保留真实 API 路径；演示入口显式选择并标识，状态写入仅在演示范围内。重构组件不能包含账号、Cookie、token、私有域名、真实人员或真实团队素材。

### 配置消费

品牌提供名称、标志、favicon、主色与说明；类型提供展示名、已安装能力和可用动作；角色以 capabilities/actions 控制；标签来自字典。存储只显示对用户有用的接收/下载能力和限制，不把供应商凭据带入界面。

主题对比度不合格时给管理者预览与修正建议；不允许任意 CSS/JS。品牌图像来源与字体许可在实际引入前核验。本阶段不提供主题编辑器、布局搭建器或新增存储适配器。

### 有界验证

每批实现先集中检查桌面和手机实际渲染，再统一修复，最多一轮复核；后续专项审查只针对剩余具体问题，不无限打磨。

- 基本视口：1440×900、1280×800、768×1024、390×844；补充当前用户视口、200% 放大与窄宽度样本。
- 输入：中文 IME、键盘搜索/筛选/详情关闭、焦点恢复、触屏无悬停、长标题/长标签/空字段。
- 状态：初次加载、保留已有列表的更多加载失败、预览失败、会话失效、409/412、批量部分失败、上传断线和结果未知。
- 媒体与性能：预留比例、加载缩略图而非默认原件、按需播放、离屏/后台停止、reduced-motion 默认静态、路由切换不重复创建任务。
- 工程：固定 Node/pnpm，运行受改动影响的类型/构建/Lint；必要流程测试验证行为，不编写重复占位实现的测试。
- 交付证据区分：模拟交互通过、真实 API 联调通过、真实媒体/服务器隔离验证通过。三者不互相替代。

首期不承诺尚未测得的容量、性能指标或所有浏览器兼容；目前没有对现有运行界面完成完整键盘、性能或异常恢复验收。
