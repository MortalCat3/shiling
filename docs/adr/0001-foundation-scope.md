# ADR 0001：独立工程基础阶段的范围

- 日期：2026-11-16
- 状态：已确认范围；工程基础已建立并通过本地验证
- 适用项目：shiling

## 背景

项目方已认可重构方向，确定使用独立新工程，并授权归档方案、详细设计与建立工程基础。旧平台仅提供业务经验，不构成数据、接口或运行兼容约束。

## 决定

当前允许：

1. 建立独立工程的目录、工作区和工具链基础。
2. 配置必要的类型、静态检查、格式及基础验证入口，建立清晰模块边界。
3. 准备不绑定个人或组织环境的工程配置、开发基础说明与占位结构。
4. 将产品方案、详细设计和明确决策以相对链接归档到 `docs/`。
5. 验证工程基础本身的可用性，并准确记录结果。

当前不包含：

- 业务功能代码，包括账号/权限、素材/上传、发布/下载、标签/集合/收藏、媒体处理和队列业务。
- 可执行业务数据库 schema、业务迁移、种子账号或真实数据导入。
- 复制旧素材、旧源码、凭据、环境文件、数据库或 Git 历史。
- 连接、修改或恢复旧线上环境，或删除旧数据。
- 正式部署、对外发布、建立公开仓库或替项目方选择最终许可证。

工程骨架不得伪装成已完成的产品；安装依赖、静态检查或占位应用启动不等于业务用例、安全边界、媒体兼容性和性能验收完成。

## 后果

基础阶段可以在不承担旧环境兼容负担的情况下推进。业务实现仍需后续明确进入对应阶段；待定的媒体、容量、运维参数与许可不因建立工程而自动获得确认。

本 ADR 只记录阶段范围，不重新定义领域模型或技术细节。产品与架构参见[重构方案](../product/refactor-proposal.md)，接口、模型和权限参见[详细设计索引](../design/README.md)。

工程验证结果见[基础验证记录](../operations/foundation-validation.md)，其中明确区分已完成的工程检查与尚未执行的业务验收。
