# 验证范围

仓库当前包含工程质量门禁、真实 PostgreSQL/Local 集成测试，以及需要已启动 API/worker 的可重复 HTTP E2E。设计文档中的全部页面、权限、媒体、文件、配置和恢复用例仍是完整验收目标；现有测试只覆盖其中明确列出的范围。

## 当前可运行

| 范围           | 命令                    | 说明                                                                                                          |
| -------------- | ----------------------- | ------------------------------------------------------------------------------------------------------------- |
| 工程质量门禁   | `pnpm check`            | 项目边界、格式、Lint、类型、构建、smoke 与全部集成测试；集成阶段需要专用 `shiling_test`                       |
| 隔离全量门禁   | `pnpm check:isolated`   | 自动创建本机临时 PostgreSQL 和受限测试角色后运行完整 check；不连接宿主数据库，结束后清理本次容器              |
| 首期后端集成   | `pnpm test:integration` | 真实 `shiling_test` PostgreSQL、临时 Local、合成数据；覆盖身份、品牌、媒体、整理、公开、清理和灾备安全        |
| API 代理安全   | `pnpm test:api`         | 先构建 API；非可信转发头、DNS 更新/失败、配置及 Secure Cookie 前置条件                                        |
| 本地 HTTP 闭环 | `pnpm test:e2e:http`    | 已启动 API/worker；内存 PNG；覆盖实际队列、存储、公开下载、分面、审计、动效关闭与自清理，需显式测试管理员密码 |

集成测试只允许数据库名和用户名均为 `shiling_test` 的非超级用户目标；执行前会核验并只重建该库中的 `shiling` schema。详细前提见[集成检查](integration/README.md)。

## 目录边界

- `contracts/`：存储、任务和外部服务提供方的合同断言；当前仍待补正式套件。
- `integration/`：真实数据库与 Local 的业务闭环；已有 `phase1-backend.test.mjs`。
- `api/`：API 代理信任与配置安全回归，不连接数据库。
- `deployment/`：[隔离 Docker 部署、重启与备份恢复验收](deployment/README.md)，只使用随机命名的新项目与卷。
- `e2e/`：已有可重复 HTTP 闭环；浏览器视觉、响应式、键盘、触屏与异常恢复仍按实际目标环境补充。
- `fixtures/`：只使用生成样例或明确允许再分发的样例，不复制私有素材库。

## 未覆盖边界

后端集成测试中的媒体主链使用内存任务适配器；仓库 HTTP E2E 另行覆盖真实 API/CSRF/pg-boss/worker/Local 图片闭环。工作台套件已纳入合成 MP4，Docker 套件已覆盖容器、持久化、重启及新卷恢复。[HTTPS 与容量套件](deployment/https-capacity.md)补充本地 CA、Cookie、代理限流、分级并发和字节边界。S3、长期压力、目标浏览器完整矩阵与生产恢复目标仍未覆盖；动效只验证结构检查与入口安全关闭，不代表可执行预览已经交付。

设计文档中的 Given/When/Then 属于验收合同，不得因代码存在、构建通过或某条合成路径通过就批量标记完成。新增测试必须保留失败路径与数据边界，禁止从开发或生产 URL 推导可清理目标。
