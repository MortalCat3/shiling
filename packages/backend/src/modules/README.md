# 计划中的业务模块边界

本文件只归档已设计职责；本轮不创建业务模块实现、路由、DTO、权限标识 或数据库表。

| 物理模块       | 后续职责                                                    | API/产品词映射                        |
| -------------- | ----------------------------------------------------------- | ------------------------------------- |
| identity       | 成员、登录身份、邀请、恢复、会话与角色                      | auth、members、roles                  |
| ingestion      | 上传批次、上传项、传输尝试、接收核验与入库协调              | uploads                               |
| assets         | 素材、不可变内容版本、内部元数据、产物与归档                | assets、artifacts                     |
| processing     | 可靠任务协调、尝试记录、栅栏与产物提交                      | jobs、processing                      |
| library        | 标签字典、团队集合、个人收藏及其素材关系                    | taxonomy、collections、favorites      |
| publication    | 独立公开快照、撤回、公开查询与交付资格                      | publications、public                  |
| administration | 经校验的产品设置、品牌候选、脱敏运维信息和业务/安全审计事件 | settings、branding、operations、audit |

API、表和权限使用业务资源名不意味着新增同名物理模块。模块获准开发后按实际需要划分领域层（`domain`）、应用层（`application`）与端口接口（`ports`）；数据库与供应商适配实现不侵入领域规则。模块通过公开用例协作，不直接改写其他模块的表。数据库迁移最终由后端统一版本化，但当前不存在迁移或数据库结构定义。

平台技术适配、编译期可信扩展的放置和依赖应随具体实现再细化，不能通过这张目录表引入在线执行插件、全局服务定位器或空泛的通用框架。
